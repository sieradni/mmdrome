# mmdrome — Developer Knowledge Base

## 0. Purpose & Usage

This file is the definitive reference for developers and AI agents working on **mmdrome**. Its purpose: a fresh session — human or agent — can work correctly **without re-deriving the codebase**, at the lowest context cost, and **without the doc lying as the code evolves**.

- **Injection**: the whole file is auto-injected at session start via `opencode.json` (`"instructions": ["AGENTS.md"]`). The injected copy is a **session-start snapshot** — if you suspect drift (file changed mid-session), re-read the file on disk.
- **Usage**: grep for symbols/anchors; do NOT re-read the file wholesale — the injected copy already contains it. Deep historical detail (the *why* behind every rule) lives in `docs/DEVLOG.md`, which is NOT injected — read it on demand.
- **Anti-rot contract** (how the doc stays correct):
  1. Every §4 rule carries anchors (file, function, or test). When you touch referenced code, verify the anchor and fix it if drifted — a doc with dead anchors is worse than no doc.
  2. When a test pins a rule's invariant, tag it `[test-enforced: …]` — the test is the real documentation; the entry stays as awareness.
  3. Untested invariants are flagged `[not test-pinned]` (gap audit 2026-08-13). Invariants that *can* be tested should eventually get tests (design rule F2).
  4. Every "do NOT X" rule exists because someone broke X — preserve the why-clause. New learnings: dated detail → `docs/DEVLOG.md`; promote to §4 only if a future session could break it and no test pins it (add the date + why).
  5. Parity claims must be RE-VERIFIED against the source before pinning — never asserted from memory (2026-08-13 lesson: a misremembered `_enterBgSeq` guard was enshrined in a test before the re-review caught it).

## 1. Tech Stack & Framework Conventions

- **Framework**: Svelte 5 (runes: `$state`, `$derived`, `$effect`) + TypeScript + Tailwind CSS v4.
- **Build**: Vite, client-side SPA. **Deploy**: manual `npm run deploy` (gh-pages) — NOT CI-triggered.
- **Design philosophy**: minimalist; no heavy UI/component libraries; native Svelte reactivity + Tailwind + simple CSS.
- **Persistence**: Dexie (IndexedDB) for settings, EQ presets, queue, and the track-metadata cache (`src/lib/db.ts`).
- **Design rule**: logic lives in pure, injectable modules (no DOM, no Dexie, fake clocks) so it can be unit-tested; thin adapters bind DOM/Swift. This is the operational form of "clean models for intended behavior, not straightforward patches."

## 2. Architecture Map

### 2.1 Web audio engine (`src/lib/audioManager.ts`)
- Dual `HTMLAudioElement`s (`a`/`b`) for gapless playback, preloading, and crossfading (≤15 s, exponential ramps via dual gain nodes); crossfade EXECUTION is gated by the pure `src/lib/playbackCore/crossfadePolicy.ts` (A12).
- Routing chain: `element → MediaElementAudioSourceNode → GainNode (Track RG) → SoundTouchNode (pitch/tempo worklet) → EQ biquad chain → preamp GainNode → destination`.
- **EQ path is BRANCHED (2026-09-13)**: all-parametric EQ runs the biquad/worklet chain; the graphic IMPORT mode OR any enabled `curve:'graphic'` band routes the WHOLE EQ through the FFT-convolver path (`_shouldUseConvolverPath()` — every routing site reads this one predicate; a convolver cannot be mixed with the biquad chain in one signal path, so parametric bands contribute their gain as curve points — `bandsToCurvePoints`). Live per-band edits go through `setEqBandParams(index, freq, gain, q?)` (NO chain rebuild); structural changes (band count) go through `applyFiltersConfig` (full rebuild). The no-worklet fallback `_buildDefaultEq` materializes the STORED configs — never revert it to a flat 10-band grid (that silently collapsed flexible/imported EQs).
- ReplayGain: track/album modes via dedicated gain nodes (`_rgGainA/B`).
- iOS background element `_bgEl` + handoff machinery — see §3.1.

### 2.2 Native iOS engine (`native/BackgroundAudio` Capacitor plugin + `native/BackgroundAudioCore` SPM core)
- JS client: `src/lib/nativePlugin.ts` (`nativeEngine`); facade: `src/lib/engineFacade.ts` (`engine` singleton — views talk to this on BOTH platforms; web delegates to `audioManager`).
- **Bridge protocol**: JS sends combined-queue snapshots (`setQueue` then `playTrackAt(index, autoPlay)`); native owns the clock; events: `trackChanged {trackId, queueEntryId?}` (**NOT index** — queue reindexing makes index mapping drift; optional `user:<id>` / `auto:<id>` distinguishes lock-screen Previous from an upcoming duplicate, with forward-relative fallback for older builds), `playbackStateChanged`, `ended`, `error`, `sleepTimerFired`, `networkStateChanged {isExpensive, isConstrained}` (low data mode; `NetworkMonitor.swift` NWPathMonitor, started unconditionally in plugin `load()`, initial path update emits the boot snapshot). `getNetworkState` answers the same snapshot on demand; `refreshQueue({tracks, activeIndex})` re-syncs the native tail without disturbing the active track (every snapshot ROW carries `queueEntryId` — `combinedEntryIds`, so Swift can name one copy of a repeated song; JS resolves `trackChanged.queueEntryId` back through `resolveQueueOccurrence` + `findEntryIndex`); `setLoopMode` for mid-play changes; `secureGet/secureSet/secureDelete` (2026-09-17c) are the Keychain credential bridge — **MUST stay listed in `pluginMethods`** (the §3.4 getMethod gate silently drops unregistered names — fatal for a credential read), and new native surface extends the EXISTING plugin rather than registering a new class: `packageClassList` in capacitor.config.json is CLI-managed and a hand-added entry can be silently dropped by the next `cap sync`.

### 2.5 UI support modules
- **Modals (2026-10-20)**: `src/components/ModalShell.svelte` is the ONE modal primitive — a native `<dialog>` opened with `showModal()` (focus containment, inert background, Esc via `oncancel`, and TOP-LAYER stacking). `PushConfirmShell` (the WebDAV push confirm pane) and `TrackDetailsModal` both render through it. **`PushConfirmShell` owns the pane's STRUCTURE, not just its name/description** (2026-10-21): the header warning, the `role="status"` file-count line, the scroll body (children = the row list) and the footer actions (`closeLabel`/`submitLabel`/`submitDisabled`/`onsubmit`) live in the shell, so `SettingsView` and the `?uiPreview` fixture cannot drift apart — do NOT re-inline that markup at a call site. Two rules with field history behind them: (1) **sizing is owned by the shell** — `max-h-[min(80dvh,42rem)]` + `w-[calc(100%-2rem)] max-w-lg`, never per-consumer `max-h` overrides (Tailwind resolves conflicting utilities by stylesheet order, not attribute order). A `100dvh`-tall pane ran under the iOS notch/home indicator/Safari bottom bar and its footer became unreachable, so the cap is what keeps the screen above and below the pane visible and tappable. ## 3. Platform Quirks

### 3.1 iOS background audio mode
iOS aggressively suspends `AudioContext` and throttles background timers/events. The PWA uses a specialized handoff mechanism owned by `WebBgTransport` (`playbackCore/webBgTransport.ts`, Step 3 of TODO 1.0):
- **Background element**: a bare `HTMLAudioElement` kept warm; playback transfers on `visibilitychange` (handler wired ONLY when `engine.isIOS` — the transport holds its own machine state, see A6).
- **Volume**: iOS ignores `HTMLAudioElement.volume` — the bg element's `volume` stays `0` forever (setting it is a no-op). Volume = master preamp while foregrounded, iOS hardware rocker while backgrounded.
- **Bypassed in bg**: SoundTouch worklet + EQ biquad chain (suspended AudioContext). Only the bg element's `playbackRate = speed` applies.
- **Media session routing**: ALL lock-screen actions (`play`, `pause`, `seekto`, `nexttrack`, `previoustrack`) call the manager, which dispatches to the transport when engaged (`sessionElement` targets the bg element while engaged) — mediaSession.ts has NO bg branches and NO audioManager import.
- **Position polling**: `timeupdate` stalls on iOS bg elements → the transport's **250 ms** tick polls position and fires `onTick` (manager refreshes `currentTime` + lock-screen position state).
- **Race protection**: the old `_handlingEnd` + sleep-park + `_enterBgSeq` trio is replaced by the machine + the transport's **settle token** (stale `play()` settles are dropped) + `onParked` reporting (the sleep park lands via `onParked(trackId)` → `sleepTimerManager.parkAtEnd` + paused state; the exit-bg park gate reports too). Queue advancement happens exactly once: the machine's trackEnded/exit-ended events are the only advance triggers, resolved manager-side (`_handleBgLoad`).
- Native iOS has its own bg path (plugin engine owns the clock; media-session commands route through the plugin) — see §2.2, E7/E8.

### 3.2 iOS viewport, safe areas & zoom
- `viewport-fit=cover` in index.html is REQUIRED or `env(safe-area-inset-*)` is always 0; `.safe-area-*` helpers in app.css (`safe-area-full`, `safe-area-x` — the latter includes left/right insets for the landscape notch); `SystemBars.setStyle` for the status bar (native only).
- **Zoom lock (3 layers)**: viewport `maximum-scale=1.0, user-scalable=no` + `ios.zoomEnabled: false` (capacitor.config.ts) + 16 px font floor on text inputs (Safari ignores `user-scalable=no`).

### 3.3 WebDAV from native
Plain `fetch` from the webview dies at CORS (the origin whitelist on the user's Cloudflare Worker hardcodes the web origin). `webdavFetch` (`webdavUtils.ts`) is the single choke point: on native it routes through `CapacitorHttp.request()` (URLSession — no CORS), translates `RequestInit`→`HttpOptions` (ArrayBuffer body→base64, binary response→chunked `atob`), and returns a minimal `WebdavResponse` shim. `NSLocalNetworkUsageDescription` in Info.plist (LAN servers). Navidrome API calls stay on plain fetch (server is CORS-enabled).

## 4. Design Rules & Invariants

### A. Audio & playback
- **A1 — Duration truth**: `track.duration` (metadata) is the sole source of duration everywhere. `HTMLAudioElement.duration` lies (NaN/truncated/short) → early track end, broken seek clamps, wrong slider max. `effectiveDuration` (appState.ts:98) is a plain `track.duration` proxy — keep exporting it (consumed by App.svelte and QueueView).
- **A2 — iOS bg invariants**: bg element `volume` stays 0; effects bypassed in bg; media-session actions route via the manager's engaged check; 250 ms tick in bg. All bg mechanics live in `WebBgTransport` (machine + settle token + watchdog + tick) — `audioManager` has NO bg code left and NO `_enterBgSeq` exists (§3.1).
- **A3 — Native params only at schedule time**: speed/pitch/tape writes happen ONLY inside `scheduleCurrentTrack`; while playing, a change goes through `paramsDirty` + `restartForParams()`. Do NOT move param writes outside the schedule-time path (§3.4). **Web parity (2026-09-13, "iOS web speed/pitch bugs out + paused loop")**: the SoundTouch worklet's pipe REWIRES its Transposer/Stretch stage order whenever the effective rate crosses 1 (`calculateEffectiveRateAndTempo`, `public/soundtouch-processor.js`); a live param write on a mid-stream (pulled) node rebinds buffers around in-flight frames and the WSOLA ring can self-feed — wrong pitch ("speed/pitch stop working"), then a looping phrase while the element is PAUSED ("loops in place"). Web rule: pipe-shape params (`playbackRate`/`pitch` on the SoundTouchNode) are NEVER written directly while `_stNodeLive` — `_markStDirty()` + debounced (120 ms) `_rebuildSoundTouchNode()` swaps in a FRESH node whose params are written pre-pull (same-value writes skip the rebuild). Element `playbackRate` writes stay live (plain HTMLMediaElement, always safe). Do NOT "simplify" back to direct `.value` writes on the worklet. Related UI rule: `PitchSpeedView.resetAll()` resets speed + pitch only, NOT tape mode.
- **A4 — Advance chain**: park → loop-one → advance → loop-all → stop, from the ONE `decideAdvance` (`playbackCore/advanceDecider.ts`); `fromError` skips the park (a dead stream can't play out its end). STOP is a uniform decision — the adapter maps it. `_onTrackEnded` now routes through it (the hand-rolled chain is gone, 2026-08-13); the only remaining copy site is `_handleCrossfadeEnd` (reconcile-driven, kept for the crossfade-rescue bookkeeping). **The loop-one bound (2026-09-20, ledger item 1): `decideAdvance` takes `errorRestartCycles` and returns `stop` instead of `restart` once consecutive error give-ups for the SAME track reach `LOOP_ONE_ERROR_CYCLE_LIMIT` (3) — a permanently broken track under loop-one otherwise restarts forever (the pre-2026-09-20 "loop a single track" report). The count lives in `PlaybackManager._errorRestartCycles` + `_errorRestartTrackId` (track-KEYED: a different current track implicitly restarts the count at the next bump; a natural end resets; a SUCCESSFUL same-track start deliberately does NOT reset — "started then died" is the same pathological cycle, and resetting on success would make the bound unreachable for exactly the truncated-stream loop). Bg cycles count via `bg.onEnded(fromError)` (the machine's raw end event, bumped BEFORE its load decision executes via facts). Do NOT reset the count on play success, and do NOT un-key it from the track — both reintroduce the unbounded loop.** `[test-enforced: tests/advanceDecider.test.ts, tests/playbackManagerAdvance.test.ts]`
- **A5 — Retry**: one `RetryPolicy` (`playbackCore/retryPolicy.ts`): web 3× exp backoff (1 s/2 s/4 s), native 2×, bg 0 (gives up on first error). The `PlaybackManager` constructor takes injectable deps (defaults = module singletons) so manager glue tests never construct a DOM (`tests/playbackManagerBg.test.ts`). Test-only TS constraints (tsconfig.test.json): `erasableSyntaxOnly` (no constructor parameter properties), `allowImportingTsExtensions`, `paths` without `baseUrl`; discriminated-union array literals need explicit `as` annotations. `tests/e2e/**/*.spec.ts` are Playwright specs (run via `npm run test:e2e`, NOT `node --test`); they're typechecked by tsconfig.test.json but named `*.spec.ts` so Node's test discovery (which matches `*.test.ts`, never `*.spec.*`) skips them.
- **F4 — Commit style**: small, logical, verified steps (check + test before committing); verify each feature/bugfix fully functional before the next task.
