# mmdrome — Developer Knowledge Base

## 0. Purpose & Usage

This file is the definitive reference for developers and AI agents working on **mmdrome**. Its purpose: a fresh session — human or agent — can work correctly **without re-deriving the codebase**, at the lowest context cost, and **without the doc lying as the code evolves**.

- **Injection**: the whole file is auto-injected at session start via `opencode.json` (`"instructions": ["AGENTS.md"]`). The injected copy is a **session-start snapshot** — if you suspect drift (file changed mid-session), re-read the file on disk.
- **Usage**: grep for symbols/anchors; do NOT re-read the file wholesale — the injected copy already contains it. Deep historical detail (the *why* behind every rule) lives in `docs/DEVLOG.md`, which is NOT injected — read it on demand.
- **Anti-rot contract** (how the doc stays correct):
  1. Every §4 rule carries anchors (file, function, or test). When you touch referenced code, verify the anchor and fix it if drifted — a doc with dead anchors is worse than no doc.
  2. When a test pins a rule's invariant, tag it `[test-enforced: …]` — the test is the real documentation; the entry stays as awareness.
  3. Untested invariants are flagged `[not test-pinned]` (gap audit 2026-08-13). Invariants that *can* be tested should eventually get tests (design rule F2).
  4. Every "do NOT X" rule exists because someone broke X — preserve the why-clause. New learnings: dated detail → `docs/DEVLOG.md`; promote to §4 only if a future session could break it and no test pins it (add the date + why).
  5. Parity claims must be RE-VERIFIED against the source before pinning — never asserted from memory (2026-08-13 lesson: a misremembered `_enterBgSeq` guard was enshrined in a test before the re-review caught it).

## 1. Tech Stack & Framework Conventions

- **Framework**: Svelte 5 (runes: `$state`, `$derived`, `$effect`) + TypeScript + Tailwind CSS v4.
- **Build**: Vite, client-side SPA. **Deploy**: manual `npm run deploy` (gh-pages) — NOT CI-triggered.
- **Design philosophy**: minimalist; no heavy UI/component libraries; native Svelte reactivity + Tailwind + simple CSS.
- **Persistence**: Dexie (IndexedDB) for settings, EQ presets, queue, and the track-metadata cache (`src/lib/db.ts`).
- **Design rule**: logic lives in pure, injectable modules (no DOM, no Dexie, fake clocks) so it can be unit-tested; thin adapters bind DOM/Swift. This is the operational form of "clean models for intended behavior, not straightforward patches."

## 2. Architecture Map

### 2.1 Web audio engine (`src/lib/audioManager.ts`)
- Dual `HTMLAudioElement`s (`a`/`b`) for gapless playback, preloading, and crossfading (≤15 s, exponential ramps via dual gain nodes).
- Routing chain: `element → MediaElementAudioSourceNode → GainNode (Track RG) → SoundTouchNode (pitch/tempo worklet) → EQ biquad chain → preamp GainNode → destination`.
- ReplayGain: track/album modes via dedicated gain nodes (`_rgGainA/B`).
- iOS background element `_bgEl` + handoff machinery — see §3.1.

### 2.2 Native iOS engine (`native/BackgroundAudio` Capacitor plugin + `native/BackgroundAudioCore` SPM core)
- JS client: `src/lib/nativePlugin.ts` (`nativeEngine`); facade: `src/lib/engineFacade.ts` (`engine` singleton — views talk to this on BOTH platforms; web delegates to `audioManager`).
- **Bridge protocol**: JS sends combined-queue snapshots (`setQueue` then `playTrackAt(index, autoPlay)`); native owns the clock; events: `trackChanged {trackId}` (**NOT index** — queue reindexing makes index mapping drift), `playbackStateChanged`, `ended`, `error`, `sleepTimerFired`. `refreshQueue({tracks, activeIndex})` re-syncs the native tail without disturbing the active track; `setLoopMode` for mid-play changes.
- Swift files: `AudioEngine.swift` (graph, segment scheduling, crossfades — the heart), `NowPlayingController.swift` (lock screen), `SessionController.swift` (interruptions), `BackgroundAudioPlugin.swift` (bridge).
- `BackgroundAudioCore` is a dependency-free SPM package holding the pure core (`LoaderState`) so `swift test` can build it on macOS (see E5).

### 2.3 State, queue & playback
- `src/stores/appState.ts` — global stores: `currentTrack`, `queue` (`userQueue`/`autoQueue`/`recentTrackIds`), `playbackState`, `settings`, `library`, `loopMode`, `shuffleEnabled`, `effectiveDuration` (appState.ts:98), `sleepTimer`.
- `src/lib/queueManager.ts` — ALL queue logic: advancement, auto-queue replenish/filtering, promotion, `_mutateQueue` re-anchor choke point. Does NOT delegate back to playbackManager.
- `src/lib/playbackManager.ts` — track transitions, play/pause/next/prev/seek, crossfade handling, bg handoff, sleep parks, native engagement. Does NOT own queue logic.
- Pure cores: `src/lib/queueMutation.ts` (mutation reducers), `src/lib/recentWindow.ts` (LRU window), `src/lib/playbackCore/` — policy (`advanceDecider.ts`, `retryPolicy.ts`, `bgStateMachine.ts`) + transport layer (`types.ts` `PlaybackTransport` contract, `webTransport.ts` fg adapter over audioManager, `webBgTransport.ts` iOS bg adapter, `nativeTransport.ts` iOS native adapter, `crossfadeReconcile.ts`, `replayGain.ts` — Steps 1–4 of TODO 1.0 landed). The `PlaybackManager` constructor takes injectable deps (defaults = module singletons; `AudioManager`'s a/b elements are lazy so the ctor is Node-safe) — the manager glue is pinned by `tests/playbackManagerBg.test.ts`.

### 2.4 Sync, metadata & WebDAV

## 3. Platform Quirks

### 3.1 iOS background audio mode
iOS aggressively suspends `AudioContext` and throttles background timers/events. The PWA uses a specialized handoff mechanism owned by `WebBgTransport` (`playbackCore/webBgTransport.ts`, Step 3 of TODO 1.0):
- **Background element**: a bare `HTMLAudioElement` kept warm; playback transfers on `visibilitychange` (handler wired ONLY when `engine.isIOS` — the transport holds its own machine state, see A6).
- **Volume**: iOS ignores `HTMLAudioElement.volume` — the bg element's `volume` stays `0` forever (setting it is a no-op). Volume = master preamp while foregrounded, iOS hardware rocker while backgrounded.
- **Bypassed in bg**: SoundTouch worklet + EQ biquad chain (suspended AudioContext). Only the bg element's `playbackRate = speed` applies.
- **Media session routing**: ALL lock-screen actions (`play`, `pause`, `seekto`, `nexttrack`, `previoustrack`) call the manager, which dispatches to the transport when engaged (`sessionElement` targets the bg element while engaged) — mediaSession.ts has NO bg branches and NO audioManager import.
- **Position polling**: `timeupdate` stalls on iOS bg elements → the transport's **250 ms** tick polls position and fires `onTick` (manager refreshes `currentTime` + lock-screen position state).
- **Race protection**: the old `_handlingEnd` + sleep-park + `_enterBgSeq` trio is replaced by the machine + the transport's **settle token** (stale `play()` settles are dropped) + `onParked` reporting (the sleep park lands via `onParked(trackId)` → `sleepTimerManager.parkAtEnd` + paused state; the exit-bg park gate reports too). Queue advancement happens exactly once: the machine's trackEnded/exit-ended events are the only advance triggers, resolved manager-side (`_handleBgLoad`).
- Native iOS has its own bg path (plugin engine owns the clock; media-session commands route through the plugin) — see §2.2, E7/E8.

### 3.2 iOS viewport, safe areas & zoom
- `viewport-fit=cover` in index.html is REQUIRED or `env(safe-area-inset-*)` is always 0; `.safe-area-*` helpers in app.css (`safe-area-full`, `safe-area-x` — the latter includes left/right insets for the landscape notch); `SystemBars.setStyle` for the status bar (native only).
- **Zoom lock (3 layers)**: viewport `maximum-scale=1.0, user-scalable=no` + `ios.zoomEnabled: false` (capacitor.config.ts) + 16 px font floor on text inputs (Safari ignores `user-scalable=no`).

### 3.3 WebDAV from native
Plain `fetch` from the webview dies at CORS (the origin whitelist on the user's Cloudflare Worker hardcodes the web origin). `webdavFetch` (`webdavUtils.ts`) is the single choke point: on native it routes through `CapacitorHttp.request()` (URLSession — no CORS), translates `RequestInit`→`HttpOptions` (ArrayBuffer body→base64, binary response→chunked `atob`), and returns a minimal `WebdavResponse` shim. `NSLocalNetworkUsageDescription` in Info.plist (LAN servers). Navidrome API calls stay on plain fetch (server is CORS-enabled).

### 3.4 Swift & AVFoundation
- `AVAudioUnitGain` does NOT exist (phantom class). Gain = `AVAudioMixerNode.outputVolume`. Graph: `playerA/B → gainA/B (mixers) → mixer → timePitch → varispeed → eq → preamp (mixer) → mainMixerNode`.
- **Native speed/pitch/tape params are written ONLY inside `scheduleCurrentTrack`** (while nodes are stopped, `refreshPlaybackParams`). Live writes on a running engine wedge the time-pitch kernel → frozen/wrong-pitch audio → `play()` SIGABRTs in `AVAudioPlayerNodeImpl::StartImpl`. While playing, a param change sets `paramsDirty` → 60 ms-debounced `restartForParams()` (re-schedule from current position, cancels armed crossfade).
- Capacitor `CAPPluginCall` accessors REQUIRE the default-value argument (`call.getInt("x", 0)`; `call.getArray("tracks", [])` + `object as? JSObject` — the `JSObject.self` overload does not compile).
- MPRemoteCommand: `.enabled` is `.isEnabled`; now-playing time/queue keys are `MPNowPlayingInfoPropertyElapsedPlaybackTime` / `PlaybackQueueIndex` / `PlaybackQueueCount` (the `MPMediaItemProperty…` variants for those three do not exist).
- Swift 6: capture a local (`let scheduledIndex = activeIndex`) before using `self` in `scheduleSegment` completions.
- Lock-screen sync: `play`/`pause`/`toggle` plugin handlers call `refreshNowPlaying()` UNCONDITIONALLY after the engine command (no-op/edge commands otherwise leave the lock screen showing the stale button); `refreshNowPlaying` threads the EFFECTIVE duration (`state.duration`), not raw `track.duration` (can be 0).
- Interruptions (`SessionController`): `.began` snapshots `wasPlayingBeforeInterruption`; `.ended` calls `onResume()` → `engine.play()` only when the note carries `shouldResume` AND playback was active.
- Native EQ mapping: `NativeFilterSnapshot` type strings map to `AVAudioUnitEQFilterType` in `AudioEngine.swift::mapFilterType` (`bandpass→.bandPass`, `notch→.bandStop`, default `.parametric`); Q→bandwidth via `1/max(q, 0.05)`.
- **Standby crossfade generation**: `AVAudioPlayerNode.stop()` fires the pending completion handler, so `refreshQueue`/`setLoopMode` (which tear down armed crossfades) must not let the standby's stopped segment fake a natural track advance — guarded by `standbyScheduleGeneration`, bumped ONLY when a crossfade is armed/in-flight (`hadCrossfade` captured before the flags clear); after `finalizeCrossfadeSwitch` the former-standby node's completion IS the natural-end trigger and must stay valid or the queue stalls.
- Native sleep timer runs on the MainLoop (survives backgrounding), cancelled in `stopPlayback()`, tears down armed crossfades at end-of-track, pauses at the natural end, emits `sleepTimerFired`.
- PROPFIND/WebDAV from Swift side: N/A — WebDAV always goes through JS `webdavFetch` (§3.3).

## 4. Design Rules & Invariants

### A. Audio & playback
- **A1 — Duration truth**: `track.duration` (metadata) is the sole source of duration everywhere. `HTMLAudioElement.duration` lies (NaN/truncated/short) → early track end, broken seek clamps, wrong slider max. `effectiveDuration` (appState.ts:98) is a plain `track.duration` proxy — keep exporting it (consumed by App.svelte and QueueView).
- **A2 — iOS bg invariants**: bg element `volume` stays 0; effects bypassed in bg; media-session actions route via the manager's engaged check; 250 ms tick in bg. All bg mechanics live in `WebBgTransport` (machine + settle token + watchdog + tick) — `audioManager` has NO bg code left and NO `_enterBgSeq` exists (§3.1).
- **A3 — Native params only at schedule time**: speed/pitch/tape writes happen ONLY inside `scheduleCurrentTrack`; while playing, a change goes through `paramsDirty` + `restartForParams()`. Do NOT move param writes outside the schedule-time path (§3.4). Related UI rule: `PitchSpeedView.resetAll()` resets speed + pitch only, NOT tape mode.
- **A4 — Advance chain**: park → loop-one → advance → loop-all → stop, from the ONE `decideAdvance` (`playbackCore/advanceDecider.ts`); `fromError` skips the park (a dead stream can't play out its end). STOP is a uniform decision — the adapter maps it. `_onTrackEnded` now routes through it (the hand-rolled chain is gone, 2026-08-13); the only remaining copy site is `_handleCrossfadeEnd` (reconcile-driven, kept for the crossfade-rescue bookkeeping). `[test-enforced: tests/advanceDecider.test.ts]`
- **A5 — Retry**: one `RetryPolicy` (`playbackCore/retryPolicy.ts`): web 3× exp backoff (1 s/2 s/4 s), native 2×, bg 0 (gives up on first error). Timers + the track-keyed validity check + the give-up action live in the ADAPTER (`webTransport.ts` — give-up fires `onTrackEnded({kind:'natural', fromError:true})` so the manager's A4 chain skips the park); the manager's `onRetry` guard is `get(currentTrack)?.trackId !== trackId`. The play()-rejection loop in `webTransport.playLoaded` is DELIBERATELY outside (autoplay-policy problem, not backoff). `[test-enforced: tests/retryPolicy.test.ts, tests/webTransport.test.ts]`
- **A6 — Bg interlock is one reducer**: `transitionBg` (`playbackCore/bgStateMachine.ts`); states: `foreground · handoff{enter|load} · bg-playing · bg-paused · park-pending · resuming`. Pinned behaviors (corrections 1–7): exit park gated on `parkArmed && (ended || atEnd)`; exiting paused states carries the bg position; exit-ended routes through `decideAdvance` (loop-one RESTARTS); `resuming + enterBg → handoff{enter}` (re-hide re-engages); pause during a handoff cancels the swap (audible element pauses); a superseded loadRequest re-routes the exit to the fg load path. The ADAPTER (`webBgTransport.ts`) is a device driver: it owns the bg element, visibilitychange, settle token, watchdog, tick, swap, park nudge — policy exits `onLoad`/`onStop`/`onParked`/`onTick`; it NEVER touches queue/stores/sleepTimer. The exit-bg park gate reports `onParked` (manager records `parkAtEnd` + paused); the engaged-pause filter (manager) keeps a swap-settle fg pause from writing 'paused' while bg audio plays. `startBgLoad` MIRRORS the src onto the fg element — an exit-resume/carry (`resumeFg`/`carryPaused`) would otherwise play the PRE-SWAP track's audio under the current track's UI/position (2026-08-13 review finding 1, pre-existing, fixed). A GENUINE bg load failure (token-valid play() rejection) RESTORES the pre-mirror fg src — the dead URL must not outlive the failed load; a pause-dropped settle (token bumped) keeps the mirror (the fg element holds the current track's src by design). `[test-enforced: tests/bgStateMachine.test.ts, tests/webBgTransport.test.ts]`
- **A7 — Crossfade RG leak**: the standby element's replay-gain is ALWAYS reset (`standbyRgGain.gain.value = _nextTrackReplayGainLinear ?? 1`) — a no-RG track must not inherit the old track's gain. On the switch, `webTransport` re-applies the ARMED `ReplayGainFields` to the engine BEFORE the ended event (1.10-3) — idempotent vs this rule in every mode. The RG **mode** itself is pushed by the manager at every `_loadAndPlay` (`setReplayGainMode(get(settings).replayGainMode ?? 'off')`) — the settings subscription's `_initialized` guard skips its startup fire, so without the push the engine keeps the 'off' default (silent no-RG until a mode toggle). The transport only carries gains, never the mode. `[test-enforced: tests/webTransport.test.ts]`
- **A8 — prev()/volume parity**: `prev()`: `currentTime > 3` → restart at 0; else back one; else (loop-all) last track; else restart. Master volume clamp is 0–2 (200 %) on native — the preamp is a plain GainNode on web but a mixer whose `outputVolume > 1` is valid.
- **A9 — Scrobble accrual**: forward seeks ≥ `MAX_SEEK_DELTA` (5 s) are never credited (playhead re-anchors); backward jumps ≥ 5 s reset `played` to 0; accrual clamped to track duration; only `navidrome-`-prefixed tracks scrobble. There is NO `nowPlaying` Subsonic endpoint — "now playing" is `scrobble` with `submission=false`, and a completed listen is `scrobble` with `submission=true` + `time` in MILLISECONDS (Navidrome parses `time` with `time.UnixMilli`; the pre-2026-08-14 code called a fabricated `nowPlaying.view` and sent seconds). `[test-enforced: tests/navidromeApi.test.ts]`
- **A10 — Pitch snap + tape persistence (store-backed, like speed/pitch)**: `tapeMode` and `snapTolerance` are dedicated writable stores (appState.ts) — NOT `updateSetting`-driven settings, and NOT restored via `_initNative`'s `settings.subscribe` (a re-added `if (sv.tapeMode !== undefined) engine.setTapeMode(sv.tapeMode)` line would re-clobber a fresh toggle with the stale `loadSettings` snapshot — that line was removed). Persistence flows through `_subscribeShared` subscriptions (`tapeMode.subscribe`/`snapTolerance.subscribe` → `setSetting` + `engine.set*`); the web audioManager callbacks (`onTapeModeChange`/`onSnapToleranceChange`) and the facade's native branches feed those stores. Restore is via `getSetting` in `_initWeb`/`_initNative` (belt-and-braces store `.set` before subscribing). **Snap tolerance unit is SEMITONES (0–0.5, default 0.15)** — not octaves; the old Settings slider was octave-scaled and its octave branch was mathematically dead (octaves ⊂ semitones, so `semitoneDist <= octDist` always). Snap = pure `snapPitchToSemitone` (`playbackCore/pitchSnap.ts`, mirrored in `BackgroundAudioCore/PitchSnap.swift`), applied at the engine boundary (audioManager `_snapPitch` web / facade native / Swift) so `engine.pitchOctaves` returns the snapped value and the view's thumb sticks to the grid. The rounding tie breaks HALF AWAY FROM ZERO on BOTH sides (TS re-implements Swift's `.rounded()` default — plain `Math.round` would round negative halves toward +∞ and diverge); the native facade also clamps pitch to [-2, 2] before snapping (web/Swift parity). `setSnapTolerance` re-snaps the current pitch on all three boundaries (widening the tolerance can pull an off-grid pitch onto the grid; a snapped value is already on-grid so the common case is a no-op). **Restore order matters**: `_initWeb`/`_initNative` restore `snapTolerance` BEFORE `pitchOctaves` (restoring pitch first would re-quantize a saved off-grid pitch against the 0.15 default). UI lives ONLY in `PitchSpeedView` (Settings no longer has Tape Mode / Snap Tolerance). `[test-enforced: tests/pitchSnap.test.ts, tests/playbackManagerRestore.test.ts]`

### B. Queue
- **B1 — Mutations re-anchor by id**: every length-changing mutation routes through `queueManager._mutateQueue` → pure `applyQueueMutation` (`queueMutation.ts`), which re-anchors `activeIndex` by the pre-mutation active id. **Invariant: `combined[activeIndex]` points at the playing track whenever it remains queued.** Transitions that change the active id (advanceTo, native re-adopt, the crossfade **rescue** — a mid-fade target removed from the queue is re-inserted at the top of the user queue via a direct `queue.update` + `saveQueue`, deliberately NOT routed through `_mutateQueue`) must NOT route through it. `null` = explicit no-op, no store write. `[test-enforced: tests/queueMutation.test.ts — 10k×6-seed fuzz, tests/crossfadeReconcile.test.ts]`
- **B2 — `removeFromUserQueue` = DELIBERATE deviation**: active-row removal anchors to POSITION, not the id — the removed id may be the playing track itself, so `indexOf` fails by construction. Semantics (2.4, decided 2026-08-14 — option b) live in the pure `queueMutation.removeFromUserQueue`: removing a preceding row decrements the anchor; removing the ACTIVE row KEEPS the index so the highlight slides to the next playable row (never the already-played predecessor); removing a following row is a no-op anchor. Removing the active LAST row lands the anchor past the new end (out of range) — every consumer bounds-checks, so it degrades like `-1` (no highlight; end-of-track advance stops since nothing follows). **Advance-chain corollary**: after an active-row removal the playing track is NOT in the queue, so `combined[activeIndex]` is the next row — the advance paths (`_hasNextQueued`, `advanceQueue`, `next`) target `activeIndex` itself (pure `queueMutation.advanceTargetIndex(q, combined, playingId)`); the plain `activeIndex + 1` would read "queue ended" and stop/wrap, or skip the highlighted row. `playingId === undefined` keeps the plain `+1` (end-of-queue refill path). Do NOT convert to the id re-anchor; do NOT "simplify" the advance paths back to `activeIndex + 1`. **Removal skips NOW, on both platforms (2.7, decided 2026-08-14)**: removing the PLAYING row advances immediately — not at the track's natural end — **when a successor exists**. `removeFromUserQueue` returns the removed id; `QueueView` reports it to `playbackManager.handleQueueRowRemoved`, which runs the same A4 chain with the park skipped (the skip supersedes the end-of-track sleep park, matching the engine's divergence stop cancelling its timer) and loop-one disabled (a removed track is unloopable — it must never restart). Native needs no JS: the 1.4 divergence `ended` drives the same chain engine-side (even under loop-one, the 'restart' engage targets `activeIndex`, which post-removal IS the next row). **No successor (the removed row was the active LAST one, or the queue emptied) → play the track out on BOTH platforms** — `handleQueueRowRemoved` early-returns when `_hasNextQueued()` is false, because the native sync guard bails on the out-of-range index (and the Swift empty-snapshot guard no-ops) so the engine finishes the song, then the natural-end chain stops/wraps; web must not cut the audio. Belt-and-suspenders for the same invariant: both loop-one RESTART cases (`_onTrackEnded` web, `_onNativeTrackEnded`) stop instead of restarting when the current track has left the combined queue — a played-out removed row can't re-engage (its index is out of range). `[test-enforced: tests/queueMutation.test.ts, tests/playbackManagerAdvance.test.ts, tests/playbackManagerNative.test.ts]`
- **B3 — Recency window**: `recentTrackIds` (`RECENT_LIMIT = 100`) is the anti-repeat LRU: Clear Queue KEEPS it, Play All RESETS it; inscribe on leaving the active slot; loop-one restarts and same-index resumes do NOT. Survives queue trims — the Clear-Queue replay case is why it exists. `[test-enforced: tests/recentWindow.test.ts]`
- **B4 — Tier-3 recycling admits user-queued tracks — intentional** (starvation tradeoff 2026-08-10; excluding `inUser` can stop playback at queue end). Do NOT "fix" without revisiting the tradeoff. Promotion COLLAPSES cross-section duplicates: `promoteActiveTrack` dedupe-appends a user slot only when none exists and slices the auto queue at the copy. `[test-enforced: queueMutation collapse scenarios]`
- **B5 — Auto-queue scope**: `albumScope`/`artistScope` set ONLY when playing from album/artist detail views (or Play All), NOT on view entry/exit; cleared on plain TrackRow play (no `onplay` prop) and on shuffle toggle.
- **B6 — Rotation anchor**: non-shuffle rotation anchors to the LAST user-queue entry (not the active track — the user may insert songs past it; the visible queue must stay stable except appended auto tracks). `queueWrapNotice` fires only when nothing ranks after the anchor (`splitAt < 0`).
- **B7 — Auto-queue follows the shared sort**: non-shuffle fill ranks the whole library with the shared `libraryFilters` sort (`_buildOrderRank`, ties by library index); a sort change rebuilds the auto queue. Album/artist-scoped pools follow the global sort too.
- **B8 — Promotion kept**: played tracks stay listed in the user queue — intended behavior (product decision 2026-08-11). `queueSize` counts `userQueue.length` only.

### C. Settings & UI state
- **C1 — Stores are the single source of truth for settings inputs**: every input calls `updateSetting(field, value)` directly on `input`. NEVER reintroduce local mirrors + debounce + sync `$effect` (the 2026-08-11 fix; the old debounce caused stale-value action clicks). `commitCredentials()` (SettingsView) trims URL/user fields and persists BEFORE any network call — every action handler awaits it.
- **C2 — Session-only state**: Settings tab/scroll persistence uses `sessionStorage` — NEVER localStorage (no credential mirroring). Restore synchronously at component init (not onMount) or the save effect clobbers it.
- **C3 — Shared filter/sort**: `libraryFilters` store is the single filter/sort source for Songs/Albums/Artists (`applyFilterSort` with any-track album/artist rating semantics via `ratingOf`; `avgRating` averages only rated tracks). Svelte `class:name` directives can't contain `/` (e.g. `class:bg-white/15` — parse error): use a computed class string.
- **C4 — Rating-slider vs scan race**: sliders commit on the FIRST `input` tick (row flips `pending_sync` instantly → scanner skips it), `dragging` guard in the re-sync effect, final commit on `change`/`blur` (modal-close mid-drag keeps the edit). All three views (DetailView/TrackOptionsView/TrackDetailsModal).
- **C5 — Cover URL cache**: `getCoverUrl` (`coverArtCache.ts`) keys by `baseUrl|username|password|trackId-size` — auth token/salt and baseUrl are baked into the URL, so switching servers or credentials must never serve stale cached URLs.

### D. Metadata / WebDAV / Navidrome
- **D1 — POPM layout is FORK-specific — do NOT "spec-fix" it** (`tagWriter.ts`): the taglib-wasm fork's model is `[owner \0][rating byte][counter(4)]` (rating immediately after the null terminator). Writing the ID3v2.3 §4.15 order (`[owner \0][counter][rating]`) reads back as **0**. The WRITE map (`ratingToMp3Popm`) and READ map (`popmToLocalRating`) are **asymmetric by design** (MusicBee-calibrated write; write 90 → POPM 204 → read 80). Do NOT align them — it breaks MusicBee interop; the read map wins on rescan. `[test-enforced: tests/tagWriter.test.ts — round-trip + asymmetry drift]`
- **D2 — Rating read scaling**: `getRating()` is normalized 0..1 for EVERY format (ID3v2 POPM/255, Vorbis RATING/100, MP4 freeform atom/100). Only `fileType === 'mp3'` uses the POPM grid (`popmToLocalRating(round(r*255))`); other formats map `round(r*100)`.
- **D3 — M4A loved flag**: MusicBee writes it as freeform atom key `LOVERATING` (no space); ID3/TXXX uses `LOVE RATING`. Find by normalized key (`k.replace(/\s+/g,'').toUpperCase() === 'LOVERATING'`).
- **D4 — Scans must skip `pending_sync` rows**: `metadataScanner.processItem` skips rows whose existing `syncStatus === 'pending_sync'` (counted scanned, not failed) — a force rescan before Push would wipe local edits. **Do NOT regress the skip.** `[not test-pinned]`
- **D5 — Push provenance**: no `webdavPath` → skipped; no `webdavBase` → skipped (legacy/unverified); `webdavBase !== current baseKey` → `wrongServer` (distinct count); `ignored` → skipped even with a path. After each successful PUT, re-check the LIVE row via the pure `shouldKeepPushPending` (`pushReconcile.ts`): newer `rating`/`loved`/`webdavPath`/`webdavBase`/`comments`/`matchSource`/`ignored` edits are re-upserted as `pending_sync` (never flattened to `synced` from the stale snapshot — flattening writes the whole snapshot back and would lose a mid-push re-bind's NEW path/base, a comment, a manual-bind marker, or a dismissal). `[test-enforced: tests/pushReconcile.test.ts]`
- **D6 — Single commit path**: `commitFeedback` (feedbackService) is the ONLY UI commit path for rating/loved. It (and `seedNavidromeFeedback`) rebuilds the FULL `LocalMetadataStore` and `put`s it (replace, not merge) — both MUST preserve `matchSource`/`ignored`, or a rating edit / server seed on a dismissed or manually-bound row silently drops the marker and the next scan re-matches/re-pushes it (D8). `[test-enforced: tests/metadataWriters.test.ts]` `ratingSource: 'webdav'` → local cache `pending_sync` (Push writes tags); `'navidrome'` → direct server writes (`setRating` 1–5, star/unstar), never `pending_sync` — UNLESS `writeTagsInNavidromeMode` (default off) is ON, which marks the row `pending_sync` so Push also writes the tag to the WebDAV file (MusicBee sees phone edits). Do NOT confuse `writeTagsInNavidromeMode` with `syncToNavidrome` — the opposite-direction mirror (webdav → server), forced ON when flipping to navidrome. `seedNavidromeFeedback`: in webdav mode, server values only seed when there's no existing entry or the row is unbound/zero — coarse server stars must NEVER clobber fine-grained tag ratings; navidrome mode: server always wins. Push of a cleared rating: push `setRating(songId, 0)` only when `rating == 0 && prevRating > 0` (an actual clear, not a heart-only).
- **D7 — Layer rule**: `navidromeApi.ts` is a stateless Subsonic HTTP layer (+ config cache `setCachedConfig`/`getCachedConfig`); `syncEngine.ts` owns ALL policy (credential resolution, baseKey-scoped cache, cache fallback, orchestration). API functions always take an explicit `NavidromeConfig`; ONLY orchestration functions pull config. Do not resurrect wrapper fossils (`connectNavidrome`, `getNavidromeSongStreamUrl` in the api layer).
- **D8 — Auto-bind requires evidence**: gate `score >= 40 && (nameScore > 40 || tagScore > 0)` — size-only (40) never auto-binds. `certain` = exact title AND exact artist — the only verdict the scanner auto-binds on. Manual bindings (`matchSource: 'manual'`) are never re-matched by scans (issue-1 guard; the bound path is re-READ on scans so tag edits propagate). The claim guard (`claimedInScan`) must claim synchronously (check+add with no await between — it's the atomicity across concurrent `processItem`s). Re-verify flows: 'conflict' REFUSES the re-stamp (would canonize a wrong binding); 'unknown' allows it (the user's click IS the verdict). Rule of thumb: automatic paths never write unverified bindings; user-initiated paths may. All bound paths are excluded from candidate suggestions.
- **D9 — Scan freshness**: `scanAll('modified'|'force')` is the only scan entry. ALWAYS a fresh PROPFIND probe FIRST (`refreshIndex`) — never scan a stale snapshot (a stale index can't detect remote tag edits; error + abort on probe failure). Exactly ONE PROPFIND per connect. Unmatched-retry gated by `computeIndexFingerprint` (FNV-1a over sorted `path|size` pairs). **Credential swap MUST bump `scanGen` AND set `cancelled = true`** (0.4) — otherwise in-flight items match against the cleared empty index and the vanished-clear branch mass-wipes every binding. Index key captured BEFORE the probe await. In `ratingSource === 'navidrome'` mode, `processItem` preserves the row's rating/loved/comments (Navidrome is authoritative; only `fileType`/`webdavPath`/`webdavLastModified`/`webdavBase` refresh).
- **D10 — Choke points**: `webdavFetch` (`webdavUtils.ts`) is the single WebDAV fetch path (native → CapacitorHttp, §3.3). Star/unstar batching ≤ 30 ids per request (GET URL length, HTTP 414). PROPFIND `Depth: infinity` falls back to `crawlIndex()` (BFS `Depth: 1`, concurrency 6). `deriveFileType` keeps the actual suffix as-is (`.wav` must stay `wav`); only missing suffixes parse the content-type through `CT_SUBTYPE_ALIASES`; unknown subtypes fall back to `mp3`.
- **D11 — taglib-wasm disposal**: `try { reads } finally { dispose }` in BOTH `extractMetadataFromBuffer` and `extractRawTagProperties` (dispose in its own try/catch); post-open errors RETHROW — never return `rating: 0` silently (it clobbers real ratings and defeats the chunk-doubling retry). `modifyMetadataBuffer` is already safe (taglib's own finally).
- **D12 — fileType must not outlive the Track**: a cached row's `fileType` never survives the library Track — always write `track.fileType` (library-stamped); Push resolves the write-branch type from the library (`fileTypeOf`), never the stale row.
- **D13 — Normalization is CJK-safe**: `normalizeForMatch` = `[^\p{L}\p{N}\s]/gu` (letters/numbers of any script survive — `\w` strips Japanese and made every CJK track a `.includes("")` near-match). `normalizeForHint` is an ALIAS — the two must not drift. Title-scoring changes only affect FUTURE scoring: healing unmatched rows needs a force rescan or the File Matching picker. `[test-enforced: tests/matchNormalize.test.ts]`
- **D14 — API normalization**: Subsonic `userRating` is 1–5 → local ×20; `starred` arrives as ISO timestamp (or boolean on some servers) — always use `isStarred()`. Navidrome search results have no rating field (no cross-source guard needed). `connectNavidrome`'s `if (!forceRefresh && lastScan)` cache guard is INTENTIONAL correctness-first — do NOT "fix" it to cache when `getScanStatus` fails. Cache is validated on `baseKey` alone (offline-start fallback; stale-cache risk accepted — "Connect & Load" forces refresh). `loadLibraryFromNavidrome` bails only when `!connected && songs.length === 0`; auto-scan gated on `navigator.onLine`.

### F. Process
- **F1 — Verification gates**: `npm run check` AND `npm test` (add `npm run build` after any src change). Swift items verify via `ios.yml` only (no local toolchain on Windows). The production-bundle smoke test (`npm run test:e2e`, Playwright) builds `dist` + serves it via `vite preview` at `/mmdrome/` and asserts the app boots with no console errors — it runs as the `smoke` job in `test.yml` (only gate that exercises the bundled output; F2b).
- **F2 — Design rule**: pure, injectable modules + thin adapters (§1). Invariants get TESTS, not prose (test-enforced tags in this file track that).
- **F2b — No module-eval cycles through eager singleton reads**: a module-level `const x = new X()` (or any constructor that runs at eval time) must NOT read a binding from a module that imports it back. Native ESM throws a TDZ `ReferenceError` on that read; the production bundle hoists the cyclic `const` to `undefined`, so the field silently becomes `undefined` at runtime. The concrete case (fixed 2026-08-14): `playbackManager`'s singleton constructor eagerly captured `sleepTimerManager` into `this._stm` (introduced by the `d6fae25` DI seam) while `sleepTimer.ts` imported `playbackManager` back for `clearLocal`'s pause; `App.svelte` imports `sleepTimerManager` BEFORE `playbackManager`, so `_stm` resolved `undefined` and `init()`/`play()` threw. Fix = invert the dependency (`sleepTimer` exposes `setExpireHandler(() => pause())`, registered in `playbackManager.init()`), AND make the manager's engine deps lazy getters (`_am`/`_qm`/`_stm` read their module singletons on first use, not in the constructor) — construction now reads no module binding at all. Break cycles with callbacks/registration + lazy reads, not eager ones. `[test-enforced: tests/moduleEvalOrder.test.ts — imports sleepTimer FIRST, asserts playbackManager._stm === sleepTimerManager]` Build-enforced too: `vite.config.ts` enables Rolldown's `circularDependency` check (OFF by default — the cycle shipped silently) and escalates any cycle touching `src/` to a hard `npm run build` failure (node_modules-only cycles, e.g. Svelte's own, are allowed).
